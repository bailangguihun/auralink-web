# 页面就绪与入场

切换路由、刷新时，正文从第一帧开始隐藏；顶部平台导航和背景保留。数据与当前批次资源就绪后，按实际视觉位置从上到下分组上浮。同页模块切换（包括社区侧栏）、提交筛选、排序及分页在对应内容区局部入场；追加时只动画新增内容。输入草稿、点赞及轮询不会触发入场。

`AppShell` 中的 `RouteMotion` 包含当前页面、页脚及返回顶部按钮，不保留旧路由，也不额外挂载其他页面。SSR 输出 `data-route-phase="preparing"`，CSS 隐藏正文并保留布局；客户端准备期间还设置 `inert` 和 `aria-hidden`。禁用 JavaScript 时，noscript 样式恢复可读的静态内容。

就绪条件包括：会话恢复结束、当前页面的加载标记结束、字体加载完成、本批图片实际解码、布局连续两帧稳定。当前 DOM 中的懒加载图片会转为 eager，避免隐藏内容与等待滚动互相阻塞；不请求尚未加载的后续分页。图片失败按已有失败占位处理。首页明确等待首张背景图，知识图表报告实际绘制状态，社区 runtime 报告初始化及并行读取状态，并观察其开放 Shadow DOM。

已有 `LoadingSection`、`LoadingStatus`、骨架、`aria-busy` 和画廊的就绪/滚动恢复标记继续生效。新的独立异步模块应从初次渲染起提供 `data-page-ready="false"`，完成或进入明确错误状态后置为 `true`。折叠面板、隐藏标签和未打开的对话框不参与本次等待。不要用长期轮询或生成任务的运行状态代替初始读取就绪状态。

## 局部内容入场

`ContentReveal` 接收 `entryKey`、`ready` 和 `label`，包住结果区，页签、搜索框、标签及排序控件放在容器外。改变 `entryKey` 后，在提交的布局阶段隐藏结果；`ready` 必须对应当前条件的响应，不能在新筛选尚未发出时沿用旧响应的 loading=false。组件保留子组件身份，不使用 React key 重挂整个模块。缓存命中的模块也在每次有效切换后播放动画，不为动效额外请求数据。

`lib/content-presentation.ts` 统一管理准备、图片解码、稳定布局、分组动画及取消；`RouteMotion` 与 `ContentReveal` 共用该实现。局部容器以 `data-content-ready` 报告就绪。祖先正在准备或入场时，子容器只报告就绪，交给祖先统一播放，避免首次进入和嵌套区域重复动画。

接入点：

- 知识库以当前 view 触发模块入场，保留已访问的统计与图谱组件。远端统计按筛选、排序、页码、重试标识匹配响应；本地统计按本地条件触发。图表重新显示时先恢复尺寸，再完成就绪标记。
- 画廊按查询和目录日期控制结果区；已有 `GalleryRows` 几何与滚动恢复逻辑保留。追加时识别新增 paintingId 的 DOM 节点，只等待并动画这些节点，已有卡片保持身份。新增图片未准备完时，加载更多保持禁用；超时显示明确错误。
- 社区原生 runtime 经 React 提供的 present 桥接相同准备逻辑；Shadow DOM 内提供对应隐藏样式。侧栏导航以 `.main-content` 管理唯一的模块入场，只隐藏当前 `.view`，侧栏始终可用，选中状态即时更新。`go` 等待本次视图的加载 Promise；帖子详情和房间快照额外提供实际完成标记，不依赖其他视图或后台读取的总数。新导航取消旧模块动画，收藏列表、详情过期响应不能覆盖新内容。同一视图的标签、搜索与排序只处理搜索用户与 feed 结果；追加 DOM 不重建原帖子。草稿层透传完整视图参数，继续执行原保存流程。

局部超时只显示该区域的错误，控件仍可用于重新筛选；整页超时继续使用独立错误页。后台预取等待当前整页及局部内容入场完成，保持既有请求共享。

入场区块互不嵌套，依照矩形位置排序；同排一起出现。动画为 opacity 0→1、向上 20px、500ms，排间间隔最多 80ms；长页压缩间隔，使最后一排最多延迟 480ms，同时保持先后顺序。用户操作会结束正在播放的入场并恢复自然几何。减少动态效果模式仍等待真实就绪，然后直接显示。

共享画作转场独立完成后才放行正文，已落位的画作不重复上浮。`RouteMotion` 只随路径变化或刷新启动；社区内部导航不发送整页入场事件。首次进入社区时，嵌套的模块准备仍由外层统一入场。

准备超过 30 秒时显示独立错误提示和重新载入入口；正文继续隐藏，不将超时当作成功就绪。快速切页会清理旧观察器、计时器及动画，旧请求完成不能放行新页面。

## 验证

常规检查：`npm run typecheck`、`npm run lint`、`npm test`、`npm run build`。

浏览器回归：指定本机 `REVEAL_WEB_URL`（默认 localhost:3000）、`REVEAL_API_URL`（必须与前端 API 配置相同，默认 localhost:5000）和 `REVEAL_OUTPUT`，执行 `npm run test:route-motion`。可用 `PLAYWRIGHT_MODULE` 和 `REVEAL_CHROMIUM` 指向已有安装；`REVEAL_CASES` 按逗号选择用例。

浏览器回归拦截所有 API，以隔离账号/数据和受控慢响应验证时序；不代表真实认证、业务写入、生成或生产性能验收。
