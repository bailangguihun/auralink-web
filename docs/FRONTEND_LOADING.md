# 前端加载体验：默认约定

适用于已有页面与未来前端功能。加载表达与数据访问权必须分开：骨架不能授权执行、推测业务进度或替代服务端状态。

## 选用组件

- `components/loading.tsx`：`Skeleton`、`SkeletonRows` 只提供纸色装饰并隐藏于辅助技术；`LoadingSection` 配合页面真实布局，提供一个可读状态。`LoadingStatus` 用于局部读操作，10 秒后说明仍在等待；只有调用方传入**只读重试**时才提供“重新读取”。没有最低展示时间、自动重试或虚构进度。
- `PendingIndicator` 用于按钮内部；同时保留按钮名称、`disabled` / `aria-busy` 和原来的业务保护。
- `DailyPaintingSkeleton` / `PaintingGridSkeleton` / `DetailSkeleton` / `KnowledgeSkeleton` / `StudioSkeleton` / `ProfileSkeleton` 对应页面布局；`MediaLoading` 为已保存媒体的读取预留容器。
- `components/page-loading.tsx` 与各路由 `loading.tsx` 只覆盖路由块加载。客户端 API 读取仍由各屏幕控制，不能仅添加路由 loading 文件。
- `components/assistant/assistant-loading.tsx` 复用已接受助手工作区 CSS：侧栏、消息区、底部输入框。登录/会话尚未核实时只显示禁用控件；不会创建会话或调用模型。
- `StatePanel` 保留 empty/error/unavailable/pending 的含义；loading 兼容入口变为紧凑读状态。新页面优先使用对应布局骨架，不用巨型通用面板占满页面。

## 读取与状态规则

1. 固定导航、标题、选项卡、筛选器和分页位置；权限已确认且无依赖的控件继续可用。分页读取中控件保留但禁止针对未知页继续操作。
2. 独立资源并行读取，各自错误、重试与空态。不要为方便写一个 `Promise.all`，把已经就绪的分区绑在无关慢请求上。
3. `useReadResource(queryKey, loader, enabled)` 适用于组件内**只读**资源。loader 使用 `useCallback`；queryKey 必须完整标识筛选、页号、目标记录。hook 加入登录 generation，仅相同账号代际 + 相同 query 的主动刷新保留内容。变更 key 当次 render 即隐藏旧数据；退出/切换账号会卸载私有工作区。响应还需通过取消与代际检查；401 清理会话，403 清理该资源。
4. 此 hook 不可用于能力授权、提交、上传、生成、支付等写操作。不能从上次成功返回的 capabilities 推断当前可执行。工坊能力读取时清空能力；助手生成状态/模型核对完成前，原回复仍可浏览，生成禁用。已有提交前校验、idempotency、UNKNOWN 和取消逻辑继续生效。
5. 相同查询后台更新应标明“暂保留已读取内容”；不同查询若保留旧页必须明确标识旧页/旧查询，并禁止误选。画廊与收藏直接以新查询骨架替换结果；工坊显示旧页页号；助手作品搜索明确说明上次查询。错误不等于无结果。
6. 重试只重新读取失败分区，绝不暗中重放写操作。AI 任务保留真实排队/执行/部分输出/取消/不确定状态；无需等待模型生成完成再出现整个工作区。
7. 不引入持久浏览器数据缓存。助手历史、附件、分支继续使用认证服务端记录；原操作账本不清空。同分支刷新保留已载入的更早消息及分页游标，切换分支/账号不混用。

```tsx
const loader = useCallback(signal => api.favoritePaintings(page, 12, token!, signal), [page, token]);
const read = useReadResource(`favorites:${page}`, loader, Boolean(token));
// auth boundary must already be verified; this is not an execution authorization.
return <section>
  <h2>我的收藏</h2>
  {read.loading && !read.data ? <LoadingSection label="正在读取收藏" onRetry={read.retry}><PaintingGridSkeleton personal /></LoadingSection> : null}
  {read.refreshing ? <LoadingStatus label="正在更新本页收藏，暂保留已读取内容" /> : null}
  {/* Independently render errors, valid data, and confirmed empty results. */}
</section>;
```

## 视觉和无障碍

- 保持纸、墨、浅边框。`content-reveal` 为 180ms 透明度变化，无延迟、不移动布局；已就绪内容立即显示。`prefers-reduced-motion` 禁用骨架、旋转和 reveal 动画。
- 图片使用服务端宽高或既有容器比例预留空间。画廊卡片仍为 4:3 cover、每日推荐和详情仍 contain；不要为骨架改动作品裁切。私有附件先读取真实尺寸；尺寸尚未知时仅使用既有预览容器的占位比例，不宣称是原图比例。
- 骨架不提供虚构数值/图例/图表点。真实标题可见、装饰 `aria-hidden`；一个读取分区一个 `role=status`，避免轮询逐条消息反复播报。慢加载只提示仍在等待，不编造百分比或预计时间。
- 局部刷新不得卸载输入框、移动焦点或把滚动强制拉到底部。错误重试按钮、分页、弹层保持键盘可达；账号变化清理私有内容优先于保留焦点。
- 新页面必须同时检验 1440px / 390px、长内容、多行输入、减弱动画、初次/返回、部分失败、401/403、快速切换和旧响应；用真实 DOM 截图，不用设计稿替代渲染证据。

## 本次读取路径审计

| 入口 | 读取范围 / 已处理问题 | 保留的业务语义 |
| --- | --- | --- |
| 路由、导航、登录恢复、小程序跳转 | 每页骨架；账号恢复紧凑状态；中止过期 profile 请求并代际隔离 | 未认证时不运行私有页面读请求；错误可明确重连 |
| 画廊 | 每日图文和网格独立；鉴权恢复结束后读取，避免匿名后立即认证的重复初读；查询切换不混用旧页 | 每日顺序与日期由 Core 给出；收藏依然由原接口处理 |
| 作品详情 | 原布局占位、服务端图片尺寸、局部只读重试 | 导览与评析仍需原显式生成操作，pending 不是读取骨架 |
| 知识库 | 统计卡和图表容器；统计/图谱可复用同账号后台预取，未命中时独立读取 | 不模拟统计和图谱；未开放、失败和空集独立 |
| 工坊 | 能力、流程列表、Creation 列表独立请求；编辑器结构稳定、列表刷新有旧页说明 | 原能力发现、上传/保存/提交约束、队列轮询、取消及 UNKNOWN 完整保留 |
| 助手 | 初始化完整工作区；同分支消息刷新不清空；抽屉/附件局部占位；模型核对时禁用生成 | 服务器消息、引用与选择卡、自动摘要 opt-in、语音先编辑、操作恢复保持原合同 |
| 个人页 | 已核实 profile 复用；收藏独立分页/错误/重试 | 登录响应缺少完整资料时仍请求 profile；收藏失败不伪装成零条 |
| 账号/首页/关于/社区 | 账号复用会话；静态页面不添加假的数据加载；未开放页面保留 unavailable | 不以 skeleton 暗示尚无后端的社区在加载 |
| 媒体、翻页、局部操作 | 解码前纸色、固定比例；已保存音频尺寸占位；紧凑待办标识与只读重试 | 不重放上传/生成；已有媒体内容和存取保护不改变 |

## 性能与证据边界

发现并修正的是明确的请求依赖与重复读取：个人页旧实现每次收藏翻页重复 profile；工坊旧 Promise.all 将编辑器展示绑在列表；知识库旧选项卡切回会重拉整份快照；助手旧刷新会先清空消息。用隔离请求记录验证计数/独立性，不能把夹具延迟说成生产提速。

图片 API 只提供现有逻辑媒体 URL，没有本次可用的缩略图变换合同；不加任意尺寸参数、不代理私有媒体。宽高预留和解码反馈属于视觉稳定性改善，不减少原文件字节。主导航与首页入口的预取交给下述队列，已登录时一并后台预热知识库图表代码。未测生产网络、LCP 或真实设备帧率，不宣称提升幅度。

## 当前页优先的后台预取

`useNavigationPrefetch` 等待账号恢复结束、文档加载完成、当前 `main`（助手为完整工作区）中没有加载骨架/忙碌状态，且视口内 `img` 加载结束，再让出两个绘制帧，按队列准备其他主要页面。无需鼠标悬停；鼠标或键盘关注某个入口时，该入口的任务优先。离屏懒加载图片和音视频不会阻塞队列。

- 代码：匿名时只预取首页、画廊、关于、登录与注册；已登录时再准备知识库、工坊、社区、助手及账号入口。匿名关注受保护入口时优先准备登录页。仅导入客户端模块和调用路由预取，不在后台挂载页面，不触发工坊提交、助手会话恢复、模型调用、流或轮询。
- 数据：共享原有会话内存缓存，预取画廊首批（30 秒）、每日推荐（60 秒），以及已登录账号的知识统计与诗词图谱（5 分钟）。前台进入相同页面会加入在途读取或复用仍有效的结果。工坊、助手和社区的能力及执行状态仍在进入页面时实时核实。
- 调度：当前页再次加载时暂停后台任务；切页后优先新页面，保留同目标的共享读取。切换账号清理原代际缓存。页面隐藏、离线、省流量或 3G 及更慢网络时暂停，条件恢复后继续。后台失败不弹错、不登出、不循环重试，实际访问仍可重新读取。
- 请求边界：后台 JSON 读取一次执行一个；已开始的模块或路由代码下载不能通过读请求的 AbortController 中断。画廊卡片、每日推荐与认证等首屏入口关闭默认 Link 预取，避免绕过当前页就绪条件。
- 开发模式：Next.js 在开发环境禁用自身的路由预取，显式模块导入仍可准备客户端代码，API 预取也正常运行；目标路由首次编译成本仍可能存在。完整的路由预取需在独立生产构建中验证，不能将开发模式或合成延迟当作线上性能结果。

匿名访问受保护模块和画作详情时，`SessionLink` 直接链接到带完整 `next` 的登录地址，画廊列表仍公开。`AppShell` 的统一会话边界覆盖页面标题与路由骨架；账号恢复期间只显示中性确认，网络失败保留凭据并提供重试。登录、注册各自使用不可提交的认证表单加载界面，避免显示通用页面骨架。

专项浏览器回归：在本地服务启动后运行 `PREFETCH_BROWSER_OUTPUT=/tmp/artlive-prefetch node tests/navigation-prefetch.browser.mjs`，可用 `PLAYWRIGHT_MODULE` 指向已有 Playwright 安装。生产预览设置 `PREFETCH_WEB_URL` 和 `PREFETCH_BUILD_MODE=production`，还会检查路由预取；所有 API 使用隔离夹具。

## 页面间切换

普通跨页面导航由 `RouteMotion` 对当前已挂载内容执行一次进场：300ms 淡入并上移 8px，680px 及以下上移 4px；登录和注册的真实表单使用 200ms 纯淡入；作品详情在实际内容出现后先展示画作，资料延后 50ms。固定顶栏独立保持位置，桌面选中下划线用 200ms 平移，手机菜单使用局部淡入。系统开启减少动态效果时取消这些进场动效。

动效不保留旧页面、不额外挂载页面、不等待退出动画才导航。初次加载、首页内部切屏、查询参数或锚点变更、收藏、筛选、追加和聊天更新不重播；浏览器前进后退及恢复已有画廊目录时跳过进场。鼠标、触摸、键盘或滚轮操作会取消正在播放或等待的进场，先恢复自然几何再交给画廊保存浏览位置。等待首次内容的资格最多保留 5 秒，加载与认证失败仍按原界面处理。

画作卡片、每日一画及收藏卡片通过 `data-artwork-link/source` 标记共享图片入口。已登录且当前标签页打开时，`ArtworkTransition` 在点击捕获阶段把已显示的公共图片直接绘制为canvas位图（不重新读取URL或异步解码副本），并同步显示纯展示的详情背景（纸色底、画框和空资料面板）。背景与主图片使用同一动画起点；背景从第一帧就是不透明纸色，只淡入面板，避免慢路由期间露出旧画廊。测量和背景共用 `ArtworkViewer`，不挂载业务页面、不读取详情。临时图片只动画 `transform` 和 `clip-path`，进入为桌面360ms/手机320ms，返回为桌面320ms/手机280ms。源图片与真实落点在交接期间隐藏，结束或中断时恢复，避免两张同画并存。

确认点击某幅画作、主动画启动后，即并行读取该作品详情；真实页面抵达时复用同一在途请求。`artwork-flight` 门控只控制内容提交：主图片和本地背景动画均完成后，才显示文字并挂载导览、评析组件。即使详情已提前返回或命中缓存，也不能在动画期间显示正文或开始后续业务读取。此前标题、作者、按钮文字及资料加载文案隐藏但保留布局。真实路由抵达后，继续按 URL、解码和连续两个稳定帧核对落点；只在几何有差异时做最多120ms校正，不重播主动画。

详情的短期读取复用位于 `lib/painting-detail-data.ts`：使用已有会话代次 `readCache`，成功结果保留30秒，共用现有条目数/字节上限，失败不缓存。只有已经点击的画作可提前读取，不批量预读目录。独立预取消费者最多一个，15秒后取消；新的作品点击释放前一个预取消费者，已进入详情页的订阅仍可继续。账号变化同步清空缓存并取消旧代次请求；用户主动重试时取消该作品原在途请求并清除已存结果，然后重新读取，不影响其他作品，不自动循环重试。

转场右栏、真实加载右栏和完成态共用 `.detail-info` 首屏最小高度，避免加载中收缩并露出页脚。动画结束后立即复用画廊中已有的标题、作者、年代；仅未知正文和事实表保留对应布局的骨架，不设骨架最短展示时间。资料慢时继续复用公开图片预览；收藏、引用动作等到取得详情才可用，收藏结果仍以会话级覆盖状态为准。

返回画廊时，按相同账号代次、视口、查询/每日顺序验证来源，立即呈现离开前的可见画廊装饰快照并收回图片；真实画廊的 `data-gallery-ready` 和 `data-gallery-restoring` 只控制最后交接，不阻塞主动画。快照仅保存一个视口，最多24个可见组/1800个节点和400万位图像素，DPR最多2；已解码图片直接绘制为canvas，返回复用原快照节点，不带图片URL、不重复请求媒体，也不读取或导出像素；不保留React页面、事件或业务动作；真实画廊选择器限定 `main.gallery-page`，避免把装饰快照识别成实际页面。直接打开详情、失效来源、视口变化或缺图时使用正常导航。

共享层不接收业务交互，背景位于图片下方和固定导航下方。背景本体承接完整点击以取消过渡，防止点击穿透到被遮住的旧卡片；手指按住背景时，普通动画结束和页面交接也不会提前移除该命中层，直到同一手势click或cancel后清理。其内部展示节点保持inert；账号变化、隐藏页面和离开路由仍立即清理。未登录、红心、新标签打开、减少动态效果或未解码图片跳过共享过渡。主动画结束后真实落点等待最多5秒，超时一起淡出图片和背景并保留正常导航；用户滚轮/触摸/键盘操作、窗口变化、其他导航、浏览器后退、隐藏页面和会话变化都会清理图片、背景及临时样式。原生路由滚动复位不取消正在播放的动画，浏览器后退仍使用既有非动画恢复。

画廊卡片和详情资料面板保留实色纸面、边框、圆角与阴影，避免这两类大面板的实时 `backdrop-filter`。图片和背景过渡期间不叠加普通路由位移。

专项回归使用 `tests/artwork-transition.browser.mjs`，覆盖冷路由、资料慢读、背景单独延长、平板横屏/手机、返回每日推荐慢读、中断和会话变化，以及鼠标/触摸背景点按、按住手势跨越页面交接和右/中键清理。所有账号/API为本地隔离夹具；点击时序和注入延迟不代表生产网络或真机帧率。

作品详情在 901px 及以上使用固定观画面板：顶部与页面内容对齐，底部保留 24px，画作以 `contain` 适配标题栏和操作栏之间的空间。右侧资料与页脚沿右列滚动，画框、返回画廊、引用发帖及收藏不会随文档滚动；900px 及以下恢复纵向排列。保留 `.detail-artwork` 和 `data-artwork-target` 供既有转场定位，勿给它们的祖先添加会改变固定定位参照的 transform 或 filter。

## 首页整屏切换

首页由 `HomeScreens` 提供两个视口高度的停靠区域：水墨开屏和功能入口。首页页脚位于第二屏内部；其他路由继续使用文档滚动及公共页脚。滚轮按手势累计后切一屏，触控板惯性不会连续翻屏；箭头、导航锚点及键盘入口共用切屏逻辑，减少动态效果设置下立即定位。

第二屏在手机或矮窗口中可独立滚动，内容不会被固定屏高裁掉。内部滚动到顶后，需要一个新的向上滚动手势才返回开屏。两屏高度随可视窗口变化，导航固定显示；切页后恢复普通页面滚动。

运行方式与实际结果见 `docs/loading-experience/README.md`；隔离夹具不使用生产账号、Cookie 或付费模型。
